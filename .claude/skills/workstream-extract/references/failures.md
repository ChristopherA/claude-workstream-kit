# Workstream Extract -- the failures behind the moves

Each heading names a move in SKILL.md; the text under it is the narrative the move's one-line reason condenses, kept verbatim from the skill as it read before the split. Read a section when its move is doubted. Nothing here adds a step.

## When it fires

Not a schedule. Any of these is enough:

- A Learning is resolved but carries no disposition marker (applied / handed off / dropped), especially where its siblings carry one. In a never-closing workstream that marker is owed the moment the Learning resolves, not at a closure that never comes.
- A phase has no open tasks left, so its completed records now compete with live ones for the reader.
- The session-start hook prints its SIZE line, or the file feels heavy while measuring light — the checkbox convention puts a completion note on one line however long it runs, so line count under-reads the cost.
- A `notes.md` sits beside workstream.md with sections nobody has dispositioned.
- A durable artifact — a doc, reference material, a spec another project needs — is still living under `.state/`.
- A never-closing workstream's standing-health Deletion Criteria have gone a cycle or more unverified.

If none holds, say so and stop. A drain that moves nothing means the symptoms were absent, not that the workstream is clean.

The list is now the record script's `fires` sub-command, one verdict per workstream with each symptom named, which the session-start hook prints too; that is the trigger this skill's opening once said nothing in the toolset owned.

## Move 1 — Extract

Every resolved Learning and settled Open Question ends in exactly one of: **applied** to a named file outside `.state/` (cite it; make the edit now if it is missing), **handed off** via `/handoff` (in this run, not "later" — and through that skill's own gate, since a write into another project is shared-visible and the user confirms it; this skill names the gate and does not pass it), or **dropped** with stated rationale, in place. Mark the disposition on the entry itself so the next pass can see it. An entry still live — an open question waiting on the task named to resolve it — stays: dispositioning it early hides open work, the same damage Move 3 refuses for a phase with an open task.

Verify each recorded disposition rather than trusting it. A Learning citing a commit can be spot-checked and usually holds. One citing a task is aspirational until that task ran. One citing a task DESCRIPTION is inside `.state/` however landed it reads: a pre-build description is precisely what Move 2 exists to remove, so the disposition expires silently the next time this skill runs — a completion note is the part of a record a drain keeps, and the only part safe to cite. One citing an Open Question never lands at all, because an OQ resolves into a decision rather than an artifact — treat it as unrouted and write the substance to a file. One citing a file this project does not GOVERN — an installed copy, a generated file, a vendored template — is provisional, not done, until the change reaches whatever governs the file; verify it there. Sweep every entry instead of reconstructing where the last pass stopped: an already-applied item simply reads present, so a full pass is self-correcting. Use `rg --hidden` whenever the named target sits under a dot-directory; a default sweep skips `.claude/` and returns falsely clean.

Then sweep outward. Findings belonging to OTHER workstreams or projects — a decision made in passing, a sibling fix, a question raised and left — go to that workstream's Backlog with provenance, or out as a handoff. For anything recorded as absorbed or covered downstream, grep the DESTINATION: if the receiving task or its criteria do not name it, it is not routed. Edit them so they do.

The disposition marker's form — at sentence start, with a date in its sentence — is what the record script scores, because a Learning that merely QUOTED a two-word marker mid-sentence was scored as dispositioned and would have passed a standing "no orphaned Learnings" criterion. The `rg --hidden` sweep is now the record script's `cites` sub-command with `--repo`, which walks the tree by python and skips no dot-directory.

## Move 2 — Condense

Only after Move 1, and the order is load-bearing: trimming before extracting destroys the insight you were about to route, and the trim looks successful either way. Always extract, then trim.

The criterion is whether the content still does work, not its age or completion. A shipped proposal is **spent** — its wording now lives wherever it shipped, where it is authoritative, and its reasoning lives in its Decision — so the block condenses to a line naming the proposal, the Decision, and the release. A protocol is **reusable** — it governs the next instance as much as it governed the last — so it survives verbatim. The test is whether a future session would consult it. Git holds the full drafting history for whatever the record drops. A Learning that carries a terminal disposition — applied, handed off, dropped, struck through — owes nobody anything and condenses in the same pass to its statement and its marker: disposition answers whether an entry still owes something, condensation answers whether it still needs to be read, and a drain that does only the first leaves the reader's problem where it was while every checkable signal reports success. Before condensing any block, grep the WHOLE STATE TREE for what cites it, on its ID and on its description both: a finished record CITES things while a load-bearing one is CITED BY something still running, and that direction is invisible from inside the record — a within-file grep found zero where six citations sat in another workstream's file. A disposition that named the block as its home is otherwise left pointing at nothing, and the file reads clean afterward.

The spent test reaches OPEN lines too. A gate line, or any long-lived open task, accretes status entries — agenda set, decided, approved, pushed — of which one is current; the rest are spent the moment a Decision records them, and the line condenses to its current agenda and queue while the history lives in the Decisions the entries already cite. Nothing else drains an open line, and one grew past every other file in its tree while every checkbox-state check read it as live scope.

A condensation of GUIDANCE text — a rule, a skill, a template — is verified by a fresh-context read of each instruction and its reason against the original, never by size: the author's own re-read of a cut that dropped thirteen reasons found none of them, and a reader holding old against new found all thirteen.

Mark a superseded Decision in place rather than deleting it; a stale Decision that reads as current is worse than a long file.

A SHIPPED Decision — its approved changes in a tagged release, its task records already condensed — is spent the way a shipped proposal is, and condenses to its heading, its reasoning paragraph and a line naming the release, with the full text left in git at the commit before; the section is restored to numeric order in the same pass. In a never-closing workstream this is the only move that drains the Decisions, which every other move makes the sink: one file reached 79 entries and 163,690 bytes there. Which Decisions have shipped is your judgment, named explicitly; the rewrite was first `condense-completed-records.py --no-tasks --decisions ...` and is now `workstream-rewrite.py decisions` (below), dry-run by default, refusing to write on a structure change. Grep for citations first as above — a condensed Decision keeps its heading, so a citation to it still resolves, and a citation to a paragraph it dropped now resolves to the tag.

When a script does the rewriting, diff the STRUCTURE as well as the content — extract the heading set before and after and compare it. A splice that cuts one line short drops a heading while every content check still passes. The same discipline applies to every probe over the file: parse records as blocks by their leading marker rather than by line, anchor ID matches to line start, and run one known-positive case through any classification count before believing it — a first-line-only scan of multi-line Learnings misclassifies most of them, and it returns a number rather than an error.

The whole-state-tree grep is now `cites`; the terminal-Learning condensation is `workstream-rewrite.py learnings`; the shipped-Decision condensation is `workstream-rewrite.py decisions`, the old script name forwarding to it for one release; and the structure diff is what every rewrite asserts itself before writing, so the caller's check is the dry run and the second run rather than a heading diff by hand.

## Move 3 — Archive completed phases in place

What is frozen in a completed task record is its ID, its checkbox state, and the evidence its completion note cites — not the evaluation prose, options, and build notes the record accumulated while it was open. A completed record longer than the rule's completion note (ID, what it was, date, evidence) condenses to that note — the date, the commit or command that is the evidence, and `reasoning in D<n>` where a Decision holds the why, so the note cites the one place that holds the reasoning instead of restating it: one release was written four times, in chat, in its Decision, in the task's note and in ACTIVE.md — whether or not its phase is ready to move. The rewrite was first `.claude/scripts/condense-completed-records.py <workstream.md>` and is now `workstream-rewrite.py records` (below), dry-run by default with `--write` to apply, carrying a dated marker so a second run is a no-op and refuses to write when a heading or a checkbox would change: a record written onto its own line while live is correctly long until the moment it closes, and owes its condensation then. Verify the pass with a diff of IDs and checkbox states before and after, which must be identical, and leave the working detail in git at the preceding commit. Deleting a record loses it and an archive tag hides it, so neither is the instrument. Beyond that, move: add an `## Archive` section at the end of workstream.md and relocate each fully-completed phase's backlog block under it, heading intact, checkboxes and condensed notes in place. The phase stops competing with live work for attention and stays resolvable in place, at its original IDs, without a tag to look in. Moving text within a file changes no bytes, so this move cannot answer a size signal by construction — condensation can, and the composition report under Record says which one a file needs.

Move a phase only when every task in it is checked. A phase with one open task stays live — a partly-archived phase hides work. Bound every scan of the Backlog between `## Backlog` and the next `## ` heading: phase headings and Decision headings are both `### `, and this move rewrites wholesale, so an unbounded scan that reaches the Decisions splices — the bounded form found three headings in a file where the unbounded one finds seventy-nine.

The rewrite is now `workstream-rewrite.py records`; the ID-and-checkbox diff is the structure fingerprint it asserts itself; and the record's phases carry `done_tasks` and `done_gates` beside the open counts, so a completed phase reads off the record.

## Move 3b — Rotate a never-closing workstream

When the SIZE line persists after a full drain — records condensed, phases archived in place, shipped Decisions condensed — the file has outgrown draining, and a never-closing workstream rotates it the way a log rotates rather than splitting the workstream. Tag the current commit `ws/<name>-<YYYY-MM-DD>` (annotated, pushed with the next push the way a closure tag is), then rewrite workstream.md to carry only what is live: the frontmatter and Purpose; the open Backlog lines under their phase headings, the gate line with its current agenda; the Decisions a live task, gate or criterion still cites; the deferred and undispositioned Learnings; the unresolved Open Questions; the Deletion Criteria with their STANDING marks; and, first under Purpose, `Rotated <date>; the record before it is at ws/<name>-<date>`. Nothing leaves history and every ID stays resolvable at the tag, which is the form the rule already gives for citing a closed workstream. Measured before this move existed: condensing the 58 shipped Decisions of a 327,221-byte file saved 47,901 bytes, far short of the 65,536 line. Verify with the record script before and after — open count, gate count and STANDING count identical, and every open line's ID present in the new file — and re-run the citation grep of Move 2 for anything outside this file that cites a dropped block, re-pointing it at the tag.

The rewrite is now `workstream-rewrite.py rotate`, and the reason its three checks exist is a hand rotation of 2026-09-04 that passed every check the paragraph above prescribes while losing content: it dropped a live operational note that the surviving critical-path paragraph cited as "the note below"; it carried a criterion's "66 Learnings, all 66 terminal" forward while moving the Learnings section to the tag, so the claim was true when written and false one commit later; and its checks all read surviving content, so none could fail on what left. A rewrite's verification has to be derived from what the rewrite REMOVED: for each block leaving, what still points at it, and for each claim staying, does the rewrite make it false.

## Move 4 — Criteria evidence

Re-check each Deletion Criterion against current evidence: file, commit, or command output. In a closing workstream this is the material for the user gate, which stays with `/workstream-close`. In a never-closing one it is the standing-health check the rule requires each cycle and nothing else runs — the criteria are health conditions rather than an exit, and a criterion that has drifted out of true is the finding. So is a criterion SATISFIED and unticked, which looks identical on the page: read the Purpose's done condition alongside the criteria, because completion has no event either, and a workstream whose done condition is met is a closure candidate that should not go on accreting follow-on rows.

A criterion satisfied by a downstream gate is satisfied only if that gate names it. Check the destination, not the declaration. A note that parks an item against a PENDING or WINDING-DOWN destination is a deferral, not a disposition: re-verify each cycle that the destination is still real and reachable.

The set-versus-instance sentence is new with the split, from a re-check that counted one inbox where the criterion named both: a criterion's evidence can be re-derived at a narrower scope than the criterion names and still read as verified, and the failure leaves no trace when the narrow scope happens to agree. The tell is a criterion naming a SET beside evidence naming an INSTANCE. No fixture can carry it; it is a judgment about scope.

## Invocation paths

- **From `/workstream-close`**, as the periodic half of a true close. Closure keeps the narrative summary, the deletion-criteria user gate, the archive, and its own inward sweep for references that break when the directory is removed; extraction and the outward cascade are this skill. Under a close this is the LAST run: nothing may be deferred, and a disposition naming a future task is not a disposition, because the tag lands before that task does.
- **From `/workstream-close` on a workstream that should not close.** Closure's own first move turns that request around and sends it here. Arriving by this path, expect a file whose bulk is completed records rather than live scope, and expect Move 3 and Move 4 to be the substance of the run.

## Record

Compute the composition rather than estimating it; hand-rolled three times in one day it came out 3.84:1, 0.54:1 and a third figure, in the direction that decides what to do.
